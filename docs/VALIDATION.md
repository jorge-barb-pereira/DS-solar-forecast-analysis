# Validation

Tests check deterministic generation, normalized bounds, rejected timestamp/value defects, known lag/target alignment, feature invariance when future observations are changed, label purging at horizons 1, 4 and 96, hand-calculated error metrics, zero-power handling, residual-quantile rank and a complete synthetic experiment.

A separate holdout-perturbation test changes all observations from the first test issue onward and verifies that model selection, validation metrics and the calibration radius remain unchanged. Timestamp-spacing checks are tested at both nanosecond and microsecond resolution for pandas 2/3 compatibility. The initial short-horizon component has 15 tests; further components are described below.

The default 120-day, seed-42 experiment selected gradient boosting on validation. On the synthetic holdout its MAE was approximately 0.01602 p.u., compared with 0.06111 for persistence and 0.04592 for daily persistence. Active-period MAE was approximately 0.03157 p.u.; observed empirical-band coverage was approximately 0.9194. These values describe the invented process only. The full run metadata is saved in `docs/results/metrics.json` and the figure in `docs/figures/`.

GitHub Actions runs tests, the publication allowlist and a complete CLI experiment on Python 3.11 and 3.12 and stores the generated synthetic outputs as workflow artifacts. The root badge links to actual run status. Generated figures are visually reviewed before inclusion.

Successful tests demonstrate software behavior on synthetic data. No historical operational model is executed, no model pickle is loaded and no real-world forecast claim is validated. Dependency versions, generator parameters and chronological boundaries are saved in each metrics JSON.
## Open-Meteo adapter checks

The optional weather workflow has offline tests for request modes, model column identity, UTC interval spacing, missing values, malformed responses, invalid configuration, metadata exclusion and redacted transport failures. An ambiguous multi-model response is rejected. The test suite never contacts the provider.

Manual live smoke checks in October 2026 used a neutral test location independent of any project data: hourly current forecasts, hourly previous-day forecasts, an archived single run and 15-minute global-model comparisons. These checks verify acquisition and response structure, not weather accuracy or historical power-model skill. Regional-model coverage can cause missing model columns and is explicitly rejected.

## Daily ensemble study

The daily study adds analytic two-/three-/four-member summary checks, rejects incomplete or misaligned days, verifies that target-day power cannot enter its own predictors, and confirms that changing held-out labels cannot change training-fold selection, calibration radius or frozen predictions. Both daily variants run in CI. Published daily results and figures are generated solely from the included fictional weather/power generator; see [daily methods and interpretation](DAY_AHEAD.md).

## Historical weather workflow

Historical request tests cover endpoint/date selection, invalid ranges, complete requested coverage and unit agreement. Evaluation perturbation tests verify that excluded GFS data and final test labels cannot affect predictor construction or parameter selection. A manual historical acquisition/evaluation was run over all of 2025 with hourly data; raw downloads and per-timestamp predictions remain local. Reviewed aggregate results are [published separately](HISTORICAL_RESULTS.md). See the [historical protocol](HISTORICAL_BENCHMARK.md) for the distinction between reanalysis verification and observed PV validation.

## Rolling evaluation and paired uncertainty

Tests check expanding windows, seven-day gaps, unique test hours, partial final windows, exact weighted bootstrap results for constant paired differences, seeded reproducibility and invalid-block rejection. Explicit partition tests verify that later test labels cannot change earlier selection or predictions. An end-to-end synthetic historical fixture checks that bootstrap point estimates equal differences in pooled MAE and that private DataFrame metadata is omitted from reports. The complete suite has 40 tests, all offline. Public historical artifacts contain aggregate results only; raw location/weather remains local. The actual-data rolling report is generated locally, rather than regenerated by CI with a withheld location.

The revised historical study requires three or four input models. Tests check the exact four-member sample variance, verify that every member contributes, reject missing members and reject a two-member historical configuration. The actual-data report compares fixed three- and four-member ensembles on identical 2025 dates, with nonlinear boosting and scaled Ridge candidates selected on earlier validation only. See [study scope and endpoint selection](STUDY_SCOPE.md).
